# Контроль маркировки

Локальное приложение для сверки контрэтикетки с Word. Документы обрабатываются в браузере и не отправляются на сервер. В комплекте образец «Сябры. Чистая» 0,7 л.

Внутри найденного контура текст читают два независимых движка: Tesseract и [PaddleOCR PP-OCRv5 для кириллицы](https://github.com/PaddlePaddle/PaddleOCR/blob/main/docs/version3.x/algorithm/PP-OCRv5/PP-OCRv5_multi_languages.en.md). Модели хранятся в `assets/models` и выполняются в браузере. Второй движок читает и всю этикетку, и каждую строку по отдельности. Он может снять неуверенность первого только там, где сам прочитал требуемое слово на том же физическом месте, и никогда — против уверенного чтения первого: если движки уверенно читают разное, слово остаётся неуверенным и не называется ни совпадением, ни отличием. Оба варианта видны в карточке и отчёте. Совпадение текста не подтверждает юридическое соответствие или размеры.

## Запуск

```powershell
npm install
npm run build
npm start
```

Адрес: http://127.0.0.1:4173. При открытии страницы загружается образец без длительного OCR; нажмите «Проверить макет» для анализа образца или сразу замените файлы своими.

После изменения исходников повторите `npm run build`. `npm test` проверяет сравнение текста и применение требований.

## Работа

1. Загрузите DOCX или TXT в UTF-8. Таблица может иметь переставленные столбцы: их назначение определяется по заголовкам. Поддерживаются двухколоночные таблицы и данные без заголовка (с предупреждением). Обычный текст разбирается по заголовкам Word, названиям разделов с двоеточием или маркерам «Раздел:», «Текст:», «Требования:». Параграфы после `***` также становятся требованиями. Инструкции без явно заданной надписи сохраняются как условия для разбора. Общие условия документа видны во вкладке требований и в отчёте; текст и условия можно редактировать.
2. Загрузите PDF либо изображение. Автоматическая проверка запускается после загрузки: вручную выделять области не нужно.
   Пустые строки столбца с обязательным текстом отмечаются для разбора, а не превращаются в якобы отсутствующий текст этикетки. Если в общих условиях Word есть рекомендация увеличить высоту шрифта на конкретное число миллиметров, необязательный переключатель запаса показывает именно это значение.
3. Сайт ищет контуры на всём листе. Если найден замкнутый контур этикетки, текст, повёрнутые надписи и штрихкод распознаются внутри него; увеличенные образцы и техническая таблица вне контура не подтверждают наличие текста на печатной этикетке. Без достоверного контура поиск идёт по всему макету и требует особой проверки человеком. Текстовый слой PDF дополняет OCR внутри контура.
4. Сайт восстанавливает строки и порядок слов по координатам. Несколько чтений объединяются только на одном физическом участке; законченные фрагменты требования могут проверяться в разных частях макета. Неоднозначные фразы автоматически перечитываются крупнее. Затем каждая строка читается отдельно (см. «Построчное чтение»). Основное чтение PDF идёт в 432 dpi; кривые PDF для строк перерисовываются до 720 dpi. Увеличение картинки не считается добавлением новых деталей, и PDF, в который вложена одна картинка, — тоже картинка. Для текстов с английскими словами подключается установленная английская модель. Контуры ищутся отдельно в нескольких цветах; расположение и ориентация количества не закреплены за шаблоном. Длинные требования сверяются по отдельным фразам, даже если они напечатаны в разных местах. Если OCR неуверенно прочитал спорный символ, раздел получает статус «Неуверенное OCR»; такое чтение не называется подтверждённым расхождением. При уверенном несовпадении показаны найденная фраза и конкретные отличия «Word → OCR». Противоречивые чтения чисел остаются неопределёнными. Нажмите на требование, чтобы увидеть соответствующий фрагмент. Размеры с `≈` — оценки по видимым символам OCR только в найденном контуре и по физической геометрии PDF при печати 1:1. Кегль PDF не выдаётся за высоту букв.
5. Количество проверяется отдельно: значение и единица берутся из столбца 3 для выбранного варианта. Пример «0,5 л» в столбце 2 не подменяет ожидаемый объём. Учитываются л / L / l, мл, смежные единицы объёма и массы; эквивалентное количество в другой единице отмечается отдельно от совпадения записи. Образец увеличенного текста и пищевая ценность «на 100 мл» не используются как количество товара. Высота количества — меньшая из высот цифр и единицы; обе оценки показаны рядом. Десятичная запятая, пропущенная OCR, восстанавливается только по отдельному компоненту печатной краски между цифрами.
6. Подпись даты измеряется автоматически. Напечатанные цифры даты / партии ищутся рядом с подписью с учётом поворота; цифры штрихкода не принимаются за дату. В пустом окне высоту будущей печати определить нельзя: приложение объясняет отсутствие замера и просит образец с нанесённой датой. Размеры окна сверяются по значениям из Word.
7. Сверьте спорные результаты и подтвердите разделы. Скачайте HTML-отчёт для печати в PDF. В многостраничном PDF каждая страница проверяется при переключении; отчёт относится к текущей странице.

## Построчное чтение

Плотный мелкий текст набран с тесным интерлиньяжем рядом с другими надписями. В прямоугольный вырез строки попадают запятые строки выше, надстрочные знаки строки ниже и куски соседней вертикальной надписи; OCR читает их как лишние знаки. Поэтому строка вырезается не прямоугольником, а по своей краске.

1. **Где искать.** Слова, уже прочитанные основными проходами, дают только места: слова одного направления собираются в строки, строки одного размера в одной колонке — в блок. Блок кончается первой и последней прочитанной строкой; строка, которую ни один проход не прочитал, оказывается внутри него.
2. **Чужая надпись.** Строки другого направления, не меньшего размера, прочитанные не хуже своих, закрашиваются: это другая надпись. Меньшая строка никогда не «забирает» краску у крупной надписи.
3. **Колонки.** В блоке из шести и более строк пустая на всю высоту полоса шире 0,45 высоты буквы — граница колонки. Строки двух колонок читаются раздельно. Одна-две строки по пробелам не делятся.
4. **Строки.** Строки разделяются по строкам пикселей с малым количеством краски. Каждая связная фигура относится к своей строке: запятая — к строке, с базовой линии которой она свисает, знак над буквой — к своей букве, сцепившиеся через выносной элемент буквы двух строк разрезаются по интерлиньяжу. Линейки, полосы штрихкода, фигуры выше букв в несколько раз и куски строк, обрезанных краем выреза, не относятся ни к одной строке.
5. **Чтение.** Картинка строки (только её краска, на белом) читается Tesseract тремя способами: в градациях серого, после бинаризации и приведённая к одной высоте. Те же картинки, расставленные на чистом листе с широким интерлиньяжем, читает PaddleOCR; широкие пробелы выключки при этом сокращаются, чтобы одиночная буква в конце строки не терялась. Слово у края, где строка обрезана вырезом, не учитывается.

Растяжение строки по ширине в 2,5 раза, которое применялось раньше, разрушало чтение отдельных строк и убрано.

## Размерные выноски технического листа

Цветные подписи вида `2,56 мм`, `5,1x5,1 мм`, `> 10 % от площади этикетки` — это заявление типографии, а не замер. Сайт обрабатывает их отдельно от текста этикетки, в четыре шага.

1. **Поиск.** Цветная выноска ищется по собственному цвету чернил (розовый, красный, синий — любой насыщенный), а не по заданному оттенку и не по месту на листе. Выноску чёрной краской, того же цвета, что текст, по цвету не отличить; за неё принимается только короткая отдельно стоящая строка (до 16 знаков, не строка абзаца), рядом с которой есть тонкий штрих той же краски, и только если в ней прочитано число с единицей. Буквы одной выноски собираются в строку отдельно для горизонтального и повёрнутого текста, поэтому две выноски, написанные рядом в разных направлениях, не сливаются. Тонкие линии размера и стрелки в число не попадают.
2. **Чтение числа.** Вырезается только сама выноска, поворачивается и читается латинской моделью. Десятичный знак проверяется по пикселям: число отдельных точек и запятых в чернилах должно совпасть с прочитанным текстом. `0 88 мм`, `084 мм`, `22мм` при запятой в чернилах считаются непрочитанными и не превращаются в 88, 84 или 22 мм. При сомнении выноска перечитывается в другом увеличении; совпавшие чтения поддерживают друг друга. Заявление, написанное в две-три строки («12,5» над «mm»), читается как одно; две выноски, стоящие одна под другой и понятные каждая сама по себе, остаются двумя.
3. **На что указывает.** Если рядом есть пара параллельных штрихов (линии-указатели или засечки со стрелками), они задают точную полосу измеряемой строки, и надпись берётся по ним. Если штрихов нет, берётся надпись, стоящая вплотную к выноске в её строке; для записи «ширина × высота» сначала проверяется знак над или под выноской. Из нескольких пар штрихов выноска получает ту, между линиями которой стоит сама, а из них — самую узкую. Одиночная выносная линия под любым углом (прямая или с одним изломом) ведёт к надписи, у которой она кончается, даже если ближе к выноске стоит другая. Чёрная выноска без линий и штрихов остаётся без привязки.
4. **Какой раздел Word.** Найденная надпись читается и сравнивается с текстами столбца 3 приблизительным поиском подстроки: он выдерживает ошибки OCR, потерянный пробел и другое число (`12` вместо `24`). Строка с текстом нескольких разделов (`Спирт 6,8 % · Сахар · Объем 0,75 л`) относится к каждому из них. Доля площади и формат окна даты привязываются по смыслу самой выноски; знак ЕАС — по квадратной форме из трёх букв.

Для каждой выноски показаны число, надпись, раздел, сверка с минимумом и **уверенность** отдельно для числа (уверенность OCR, совпадение повторного чтения, проверка десятичного знака) и для привязки (по линиям размера и по выносной линии — высокая, по соседству — средняя). Выноска с низкой уверенностью перечисляется, но в поле размера не попадает. Выноска одной строки не распространяется на раздел, остальной текст которого набран другим размером. Если для проверки есть несколько выносок (цифры `4,2 мм` и буква `л` — `3,0 мм`), решает меньшая.

Число из выноски никогда не подменяет замер: измеренное по растру значение имеет приоритет, а выноска показывается рядом. При известном масштабе сайт находит ту же надпись на печатной этикетке и сообщает, согласуется ли с ней выноска. Расхождением считается только грубое несовпадение (потерянная запятая, не та надпись); оно получает статус «Выноска ≠ замер».

Автоматическое совпадение не согласовывает макет. Сложные шрифты и плотный текст могут давать ошибки OCR. Знаки, образец даты, читаемость, неизвестные границы и неоднозначные измерения остаются на проверке специалиста. При нескольких этикетках на странице выбирается один наиболее подходящий контур. Правила берутся из Word, юридическую актуальность система не определяет.

«Текст найден» означает, что подтверждены слова и их порядок внутри связной фразы или каждого законченного фрагмента требования. «Слова найдены» означает, что слова встречаются на листе, но связная фраза не восстановлена. «Проверить OCR» показывает конкретные отличия распознанного текста; это не доказательство ошибки печатного макета. Найденные фразы и отличия также включаются в HTML-отчёт.

Состояние живёт в текущей вкладке. При перезагрузке проверки сбрасываются. Хранилища проектов и совместного согласования пока нет.

Таблицы «что видно на макете — что выдала программа» по всем разделам двух макетов San Remino и по 44 выноскам трёх техлистов находятся в `AUDIT_SAN_REMINO.md`. Результаты личной сверки каждого из 17 разделов образца находятся в `AUDIT_SAMPLE.md`, независимые ожидаемые результаты — в `tests/fixtures/sample-human-reference.json`. Эталон образца используется только для аудита и тестов, не для распознавания других этикеток.

## Проверка на реальных прогонах

- `npm test` — логика сравнения, геометрия строк и выносок на нарисованных листах разных компоновок, и три сохранённых чтения реальных листов (`tests/fixtures/run-*.json.gz`: слова обоих движков, перечитанные места, выноски; пикселей макетов нет). Сохранённое чтение оценивается той же функцией `assess`, что и на странице. Это проверка логики, а не OCR.
- `npm run test:browser` — свежий OCR образца в Chrome: контур, название, штрихкод, количество, построчное чтение, растровый PDF, второй показатель площади.
- `npm run audit:sample` — по каждому разделу образца: что видно на макете и что отвечает программа на сохранённом чтении последнего прогона.
- `npm run run:browser -- --docx требования.docx --art лист.pdf --out прогон.json` — прогон любого листа в Chrome с выгрузкой всего состояния страницы (`?audit`, `window.__labelCheckState`).
- `npm run fixture:callouts -- листы.json` — строит `tests/fixtures/callout-readings.json` из таких прогонов; с `--check` только сравнивает чтение выносок с эталоном, с `--runs` сохраняет и чтения листов для тестов. Эталон связей (`expected`) скрипт не выдумывает: он переносится из прежнего файла, а для нового листа связи программы пишутся в `proposed` — их сверяет с листом человек.

GitHub Actions запускает `npm test` и сборку на каждом push и pull request.

## Vercel

Приложение статическое: Build Command `npm run build`, Output Directory `dist`. Репозиторий подключён к Vercel пользователем; push в `main` запускает сборку, если включено автоматическое развёртывание. `assets` содержит документы образца.

## Откуда берётся масштаб

- **PDF.** Масштаб задан геометрией страницы при печати 1:1.
- **JPG, PNG.** В файле может быть записано разрешение (JFIF, Exif, pHYs), но это число нередко проставляет редактор по умолчанию. Поэтому сайт дополнительно читает на листе заявленный размер этикетки («Размер этикетки: 60.00x80.00», «Размер готовой продукции … 103x54») и сравнивает его с найденным контуром. Разрешение принимается, только если оба источника сходятся в пределах 2–3 %: тогда в блоке «Физический масштаб» стоит «подтверждён». Если разрешения нет, а обе стороны контура дают один масштаб по заявленному размеру, масштаб выводится из него с пометкой «по размеру этикетки» (один источник, уверенность средняя). Иначе масштаб не определён и по растру ничего не измеряется.
- Контур этикетки предварительно уточняется по линии высечки: линия нарисована одной насыщенной краской, а примыкающие к ней плашки (вылеты, лак) бледнее или другого тона. Контур ровно заявленного размера считается этикеткой при любом расположении на листе; общий контур двух соседних панелей этикеткой не считается.

## Точность размеров

Миллиметры вычисляются из `PDF.js PageViewport`: размер в единицах 1/72 дюйма умножается на 25,4/72. Viewport уже учитывает CropBox, поворот и UserUnit; повторно умножать UserUnit нельзя. Расчёт описывает файл при печати 1:1, а не масштаб будущей печати. Кегль шрифта не выдаётся за высоту буквы: высота определяется по видимым пикселям символов.

PDF бывает двух видов. Если текст в нём — кривые, строку можно перерисовать крупнее, и шаг растра действительно уменьшается. Если страница — одна вложенная картинка, перерисовывать нечего: её разрешение и есть предел. Сайт различает это по содержимому страницы. **PDF образца «Сябры» — именно картинка 300 dpi**, а не кривые, как утверждалось раньше; шаг его растра 0,085 мм, и интерфейс теперь показывает это число вместо 0,059 мм рендера.

Для PDF с кривыми при 432 dpi шаг растра около 0,0588 мм, при перерисовке строк в 720 dpi — 0,0353 мм. Для картинки и для PDF с вложенной картинкой шаг равен шагу самой картинки. Интерфейс показывает худший шаг из реально использованных изображений; увеличение картинки не улучшает заявленное разрешение. Два пикселя используются только для отметки пограничного замера, не как доверительный интервал полной погрешности. Ошибки границ OCR, сложный фон и различная форма букв могут давать большую ошибку. Для обычного текста берётся медиана высот уверенных букв каждого найденного слова, затем минимум этих медиан; это оценка типичной высоты, не сертифицированный минимум всех букв.

Процент предупреждения — площадь охватывающего прямоугольника найденной надписи, делённая на площадь найденного прямоугольного контура, умноженная на 100. Это не площадь чёрных пикселей и не готовое юридическое заключение о методике измерения. Для фигурного контура, наклонного текста под произвольным углом и иной трактовки площади нужен отдельный замер. Без уверенного контура процент не рассчитывается.

Если типография на техлисте считает долю по своей формуле («S надписи = 359,9 мм² > 10 % от S этикетки, исключая место для ФСМ (318,1 мм²)»), рядом с прямоугольным показателем выводится второй, по этой формуле. В нём раздельно названо, что заявлено и что измерено:

- **по числам техлиста** (заявлено, не измерено): 359,9 мм² / 3181 мм² = 11,3 %; база 3181 мм² получена из заявленных «10 % = 318,1 мм²»;
- **сверка по растру**: прямоугольник надписи ≈ 380 мм² — с заявленным согласуется (расхождение до 10 %); контур этикетки ≈ 5564 мм², значит из базы исключено ≈ 2383 мм², 42,8 % контура;
- **смешанная оценка** — надпись по растру к базе типографии: ≈ 12 %, и она названа смешанной.

Саму зону, исключённую из базы («место для ФСМ»), программа на макете не измеряет: на листе она ничем однозначно не очерчена, а придумывать её границу по одному образцу значило бы подгонять шаблон. Поэтому знаменатель второй методики остаётся числом типографии. Прямоугольный показатель (≈ 6,8 %) не заменяется, статус раздела остаётся «Проверить размеры», какая методика применима — решает специалист.

Для изображения 300 dpi шаг растра 0,085 мм: буква высотой 0,8 мм занимает около 9 пикселей. Значение в пределах двух шагов от минимума получает статус «Пограничный замер».

Можно ли уточнить высоту точнее шага — проверено опытом (`scripts/experiments/subpixel_height.py`): буквы точно известной высоты рисуются крупно, уменьшаются до 300 dpi со случайным сдвигом, размываются и сжимаются в JPEG, затем измеряются тремя способами. Среднеквадратичная ошибка для прописных букв 0,8–1,0 мм:

| Способ | Ошибка | Завышение |
|---|---|---|
| счёт целых пикселей при 300 dpi | 0,03–0,06 мм | +0,02 мм |
| сглаженное увеличение в 2,4 раза и счёт (так сайт читает отдельную строку) | 0,02–0,035 мм | +0,01…+0,03 мм |
| края в градациях серого с интерполяцией между пикселями | 0,03–0,06 мм | +0,03…+0,05 мм |

Что уточнилось: сглаженное увеличение уже даёт примерно вдвое меньшую случайную ошибку, чем целые пиксели. Что не уточнилось: разбор краёв в градациях серого для букв до 1 мм не точнее — тонкий штрих на таком растре не достигает полной плотности краски, и его край уезжает наружу; он лучше только для крупного шрифта (2 мм: 0,006–0,016 мм). Важнее случайной ошибки систематическая: округлые буквы (О, С, З) выходят за линию прописных на 0,03–0,09 мм, а текст из строчных даёт высоту строчной буквы, на 0,2 мм меньше прописной. На трёх реальных листах оценка по растру выше заявленной типографией на 0,01–0,06 мм (0,88 → 0,94; 0,939 → 0,97; 0,905 → 0,94), то есть ведёт себя так же. Вывод: по растру 300 dpi 0,80 и 0,85 мм не различить; 0,80 и 0,90 мм — на пределе. Такие оценки годятся, чтобы заметить грубое нарушение или подтвердить выноску, но минимум 0,8 мм при замере 0,84–0,95 мм они не подтверждают. Для текста из строчных букв оценивается высота строчной буквы, для прописных — прописной; какая из них имеется в виду в требовании, сайт не решает.

Если у раздела несколько минимумов для разных предложений («для указания срока годности — 2,0 мм; для условий хранения — 0,8 мм»), каждый измеряется на своих предложениях: минимум относится к тому предложению, в котором раньше встречаются слова его предмета.

## Что сравнение текста считает отличием

- **Отличие текста** — другое или лишнее слово, прочитанное уверенно, либо слово Word, которого нет на своём месте. «Нет на месте» утверждается в двух случаях: слово отсутствует между двумя прочитанными соседями, и ни один проход OCR не увидел между ними никаких знаков; или слово должно стоять с края фразы, это место перечитано крупнее и оказалось пустым либо занятым другими словами (см. ниже). Это повод сверить оригинал, а не доказательство: уверенное чтение тоже бывает ошибочным.
- **Неуверенное OCR** — слабое чтение, похожие знаки (`Е330` и `ЕЗЗО`, `0` и `О`, `ООО` и `000`), число, от которого осталась часть (`40` → `0`), слова с края фразы, место которых перечитать не удалось. Сюда же относится разногласие чтений: один проход читает `190`, другой на том же месте уверенно читает требуемое `100`; или два движка уверены в разном. Такие случаи не называются расхождением.
- **Вставка на этикетке.** Слова, напечатанные внутри фразы и отсутствующие в Word, показываются одним отличием, а фраза вокруг них находится целиком. Раньше короткое обрезанное чтение строки выигрывало у полного, и вставка терялась вместе с началом фразы: так была пропущена вставка «из сортов винограда европейско-азиатской группы» в первой строке состава «Дольче».
- **Слова рядом с фразой** — строка соседней колонки или строка выше, которую порядок чтения вплёл во фразу, — отличием не считаются: вставленные слова стоят в потоке фразы (на строке предыдущего слова после него, на строке следующего перед ним или между ними).
- **Одно слово, прочитанное дважды** на одном месте разными проходами, не считается повтором на этикетке.
- **Пробелы.** Узкий шрифт теряет пробел в чтении (`СРОКГОДНОСТИ`) или получает лишний (`ИСПРАВ ЛЕННАЯ`). Буквы и их порядок те же, поэтому такое чтение принимается за слова, которые оно составляет. Числа так не склеиваются и не разрезаются: группировка цифр — это их значение. Другая буква (`СРОКТОДНОСТИ`) — другое слово.
- **Слова с края фразы.** Слово Word до первого или после последнего прочитанного слова может отсутствовать на макете или быть непрочитанным. Место, где оно стояло бы (продолжение строки и соседняя строка), перечитывается крупнее. Если там нет печати размером с букву (линейки, рамки, плашки и окна не в счёт) или уверенно прочитаны другие слова, включая надпись другого направления, которую подтвердили два прохода, — слова на макете нет, и показано, что стоит на его месте. Если требуемые слова прочитаны там, но не вошли в связную фразу, это сообщается. Если печать есть, а прочитать её не удалось, либо эти слова напечатаны в другом месте этикетки, ничего не утверждается.
- Латинские и кириллические буквы одинакового начертания (`BY` и `ВУ`) считаются одним и тем же оттиском.
- **Другая запись единицы** — слова и числа совпали, но единица записана эквивалентно (`г/л` вместо `г/дм³`). Величина та же; допустимость записи решает специалист.
- Концентрация (`75 г/л`) не принимается за количество товара.
- Поднятые над строкой цифры Word читаются как знаки, которые они заменяют: `25 ⁰С` → `25 °С`, `дм³`.

## Что автоматизировано, а что остаётся специалисту

Автоматически: разбор требований из таблиц и текста; поиск контура и масштаба; сверка слов и порядка с показом отличий; количество и единица; штрихкод по полосам; оценка высоты букв и доли площади при известном масштабе; чтение и привязка размерных выносок; сравнение выноски с растром.

Остаётся спорным и требует человека:

- **Плотный мелкий текст.** После построчного чтения на образце «Сябры» уверенно найдены 12 из 13 разделов, текст которых есть на этикетке (было 6). Неуверенным остался абзац с кодами `ТР ТС 021/2011`: оба движка читают «ТР ТС» слабо. Знаки одного начертания (`ООО` и `000`) OCR различить не может; такой раздел остаётся неуверенным. Это три листа, а не статистика: на другом шрифте и другой вёрстке результат может быть хуже.
- **Слово «нет на макете».** Утверждается при пустом месте между прочитанными соседями, а для слов с края фразы — после повторного чтения их места. Вывод о крае зависит от того, насколько точно найдено место; он верен на двух проверенных этикетках и остаётся поводом посмотреть на макет.
- **Проценты площади.** Прямоугольный показатель и показатель по формуле типографии выводятся рядом. Зона, исключаемая из базы, по макету не измеряется; выбор методики за специалистом.
- **Миллиметры около минимума.** По растру 300 dpi 0,80 и 0,85 мм не различить (см. «Точность размеров»).
- **Знаки и окно даты.** Размер ЕАС и формат окна берутся только из выносок; сами знаки и высота будущих цифр даты по макету не измеряются.
- **Выноски других типографий.** Чёрные выноски, наклонные выносные линии и заявления в несколько строк проверены только на нарисованных листах: реальных листов с такими выносками не было. Чёрная выноска без штриха или линии рядом не распознаётся; доля площади, написанная чёрным, не читается. Выноска, рядом с которой нет ни надписи, ни линий, остаётся без привязки.
- **Привязка по соседству** (без линий размера) имеет среднюю уверенность: выноска могла быть поставлена рядом с другой надписью.
- **Время.** Построчное чтение двумя движками добавляет около 30 секунд: образец проверяется примерно за 110 секунд вместо 80.

Разбор текста и OCR не гарантируют 100% точности. Высота около минимума, разные чтения числа, отсутствие масштаба или неоднозначная инструкция требуют проверки. Для дальнейшего повышения качества нужен корпус разных реальных макетов с эталонной разметкой текста и связей между размерными выносками и надписями; OCR не заменяет отсутствующие символы словами из требований.
